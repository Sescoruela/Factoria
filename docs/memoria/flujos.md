# Flujos

## memory-init
1. Analizar actividad Git de los últimos 30 días.
2. Proponer tipo `active` o `maintenance`.
3. Detectar tecnologías y módulos de forma conservadora.
4. Construir una propuesta de memoria sin escribir archivos.
5. Mostrar la propuesta al usuario.
6. Exigir confirmación explícita.
7. Escribir `AGENTS.md` y la memoria detallada correspondiente.

## memory-update
Pendiente de implementación. Debe revisar la memoria completa, presentar primero un resumen de cambios con su evidencia y escribir solo tras aprobación.

## feature y fix
Pendientes de implementación en hitos posteriores. Deben consumir la memoria antes de explorar el repositorio y actualizarla únicamente cuando el cambio altere información persistente relevante.
